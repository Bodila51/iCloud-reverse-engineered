# The Homecloud prompt

Before you paste it, switch Claude Code to **Auto** mode, so it runs commands without asking you each time: in the Claude desktop app's **Code** tab, choose **Auto** in the mode menu under the prompt box (Cmd+Shift+M on a Mac, Ctrl+Shift+M on Windows); in a terminal, press Shift+Tab until it shows **auto mode on**.

Then copy the text in the box below, and paste it into Claude Code on the computer that will keep your photos. On GitHub, the copy button is at the top right of the box.

Claude Code checks your computer by itself, explains the two ways to move your photos, and asks you at most two questions. Then it shows you one plan, with the few things you do yourself, and waits for your yes. After that, it runs the plan to the end. It asks again only before a step that deletes data or cannot be undone. Homecloud itself never deletes anything. [docs/two-paths.md](docs/two-paths.md) compares the two ways.

If **Auto** is not in the menu, keep the mode you have. Claude Code then asks before each command, and you approve each one.

```text
Goal: Move my iCloud Photos library to this computer in full quality, put it in Immich (a free photo app that runs on my own computer), and let my iPhone reach it through Tailscale, so I can stop paying for iCloud storage. Use the Homecloud kit at https://github.com/Bodila51/iCloud-reverse-engineered. I am not a programmer. Use plain words in my language.

How to work with me: find out by yourself what you can, instead of asking me. Ask me at most two questions. Then show me one plan, with the few things I do myself, and get my yes once. After that yes, run the plan to the end without asking again. Ask again only before a step that deletes data or cannot be undone. Homecloud never deletes anything, and turning off iCloud Photos and changing my plan stay with me, last. Tell me in one line what you are doing at each stage, and say clearly when you need me.

Done means: every photo and video in my iCloud Photos is on this computer and checked "N of N", Immich holds the same library and its check passes, my iPhone reaches Immich through Tailscale, a second copy on another drive has passed its check, any Path A sign-in is ended, and you have given me the steps to turn off iCloud Photos and change my plan. If something is left, say exactly what.

Steps:
1. If this session is not in Auto mode, tell me in one sentence how to switch: in the Claude desktop app, choose Auto in the mode menu under the prompt box (Cmd+Shift+M on a Mac, Ctrl+Shift+M on Windows); in a terminal, press Shift+Tab until it shows "auto mode on". Then go on.
2. Check this computer without changing anything, and do not ask me what you can find out: the system and its version, the processor, the memory (RAM), the free space on each drive, any external drives, and whether Docker Desktop, Tailscale, Python, and git are installed. On a Mac, look for a Photos library and its size on disk. On Windows, look for iCloud for Windows and its iCloud Photos folder. If this is not my own computer, for example a cloud session, stop and tell me to start a Local session on my own computer. On Linux, tell me that the kit's setup covers macOS and Windows, and that only Path A's download runs here. You may read the kit's files online, but do not download anything yet.
3. From what you found, pick a folder for the copy, called DIR below, with room for the whole library. Keep it out of folders that sync to a cloud service, such as Desktop and Documents with iCloud Drive on a Mac, or folders that OneDrive backs up on Windows. Pick another drive for the second copy, such as a connected external drive. Path A and B1 need about 2.2 times the library, B2 about 1.1 times, and B3 about 2.2 times plus the iCloud Photos folder on drive C:, as docs/two-paths.md lists. If you cannot see the library's size yet, say so. Step 9 checks the space again before any download.
4. Explain the two ways to move my photos, in a few short sentences each:
   - Path A, sign in to iCloud.com: scripts/icloud.py downloads every original from iCloud's servers, on a Mac, Windows, or Linux, also straight to an external drive. Before it starts, it shows the count and size per year. At the end, it checks every file against iCloud's own list as N of N. I type my Apple Account password once, in my own Terminal or PowerShell window, and it goes only to Apple. Until it signs out at the end, a session key in ~/.homecloud/session opens what iCloud.com opens: Photos, iCloud Drive, Notes, Contacts, Calendar, Reminders, iCloud Mail, and Find My. It does not open Keychain passwords, Messages, or Health. Any program that runs as me on this computer could read the key. The script sends only read requests to Photos. It is unofficial, so a change at Apple can break it. With Advanced Data Protection, I must allow web access on my iPhone first.
   - Path B, no sign-in: Apple's own apps download the originals with the sign-in I already have. Nobody asks for my Apple password, and no key stays on this computer. B1 is the Photos app on a Mac, and the only option that checks every file against its original. B2 is the Immich app on my iPhone, with any computer, and takes hours or days for a big library. B3 is iCloud for Windows on a PC, whose drive C: needs room for the whole library. B4 is Apple's data copy at privacy.apple.com, which can take up to 7 days and arrives as zip archives. B2, B3, and B4 compare the counts with my iPhone.
5. Ask me these two questions in one message, and wait for my answers:
   a. Which way? Recommend one, with one reason: Path B if my Apple account holds a lot of sensitive data, such as mail, notes, or documents, or if I want no key on this computer even for a day; Path A for a big library, for Windows or Linux, or for a copy straight to an external drive. For Path B, name the option that fits this computer. Both ways are fine, so never push me to one.
   b. Will this computer be at home and switched on most of the day? Yes means Always on mode. No means Home archive mode. If I ask for Hybrid or Offline vault instead, use that mode. If docs/modes.md says Hybrid is not ready, tell me.
6. Show me one plan: my path and my mode, with what the mode gives up in one sentence from docs/modes.md; DIR and the drive for the second copy; what you will run, in order; about how long it takes; and a short numbered list of what I do myself, and when. If my mode needs a setting that Apple or Microsoft does not document, such as pmset disablesleep, say so in the plan, with how to undo it. In Offline vault mode, the plan includes Immich, to browse the photos on this computer, unless I say I do not want it. Ask for my yes once. If I change something, show the changed plan and ask once more. After my yes, do steps 7 to 13 without asking again.
7. Clone https://github.com/Bodila51/iCloud-reverse-engineered into a new folder named homecloud inside the current folder. If git is missing, download https://github.com/Bodila51/iCloud-reverse-engineered/archive/refs/heads/main.zip and unzip it there instead. Read CLAUDE.md, README.md, the files in docs/, and the help of each script before you run it, and follow them.
8. Set up the computer with one command, from the kit folder. On a Mac: bash scripts/setup.sh --yes. On Windows: powershell -ExecutionPolicy Bypass -File scripts\setup.ps1 -Yes. It installs what is missing (Docker Desktop, Immich, Tailscale, and on Windows Python), creates my Immich account and an API key for the import, connects this computer to Tailscale, and opens a page for my iPhone. Before you start it, tell me what to expect: on a Mac without Apple's Command Line Tools, a window offers to install them, and I click Install, then Agree; my Mac asks for its password, or Windows asks for permission, to install apps; a window asks me to choose an email and a password for Immich; a browser window asks me to sign in to Tailscale or to create a free account; and on a Mac, macOS asks me to allow Tailscale's system extension and VPN configuration. Go on when it ends with "Result: OK". If it stops, tell me in one sentence what it printed, fix the cause if you can, and run it again. It skips what is done. On Windows, exit code 3 means Windows must restart to finish WSL 2: tell me the sentence it printed and how to come back to this session, and run the same command again after the restart. In Offline vault mode without Immich, skip this step. With Immich, add --no-tailscale on a Mac or -NoTailscale on Windows. When the phone page opens, tell me I can install the two apps and sign in now, and tap Enable Backup when you say so.
9. Copy my photos with the way I picked. Before any download, compare the free space with the size of the library. Path A's scan shows the size. For Path B, if you do not know it yet, ask me to read it on my iPhone under Settings > my name > iCloud. For B2, B3, and B4, ask me at the same time to read the number of photos and the number of videos, as README.md describes. I type them here. These numbers are not secret.
   - Path A: use Python 3.10 or newer, in a virtual environment with the packages in scripts/requirements.txt, as README.md describes. On Windows, the setup already made sure that Python 3.10 or newer is there. On a Mac with only Python 3.9, first install the current Python 3 from python.org with its macOS installer. I may need to click through it and type my Mac password. Give me one command for my own Terminal or PowerShell window that runs scripts/icloud.py login with that Python. I type my Apple Account email, password, and code there myself. Then run python3 scripts/icloud.py scan and show me the count and size per year. If DIR does not have room, stop and tell me. Then run python3 scripts/icloud.py download --to DIR in the background, with caffeinate -i in front on a Mac, and report its progress now and then. If it stops, run it again. It skips finished files. Then run python3 scripts/icloud.py verify --to DIR. Go on only if it reports N of N and exits with code 0. When you run verify and every file is there, it signs out of iCloud and deletes the session key by itself. Add --keep-session only in Hybrid mode.
   - Path B1, the Photos app on a Mac: install osxphotos as the top of scripts/mac/export_photos.py describes. Run python3 scripts/mac/export_photos.py check --to DIR. If originals are still only in iCloud, tell me to select "Download Originals to this Mac" in Photos > Settings > iCloud, and run check now and then until it reports 0. If the Mac lacks space, stop and show me how to move the Photos library to an external drive, as README.md describes. I do that myself. Then run caffeinate -i python3 scripts/mac/export_photos.py export --to DIR in the background, and report its progress. Go on only if it ends with "Result: all N files are copied and verified." and exits with code 0. Exit code 2 means some originals are still only in iCloud, so wait and run it again. If macOS does not let it read the Photos library, follow docs/troubleshooting.md.
   - Path B2, the Immich app on my iPhone: tell me to do the steps on the phone page now, with Recents selected for backup, and to keep the app open on its backup screen, with the iPhone charging and on Wi-Fi, until Remainder shows 0.
   - Path B3, iCloud for Windows: if it is missing, tell me to install it from the Microsoft Store. Walk me through its settings as README.md describes, until every file in the iCloud Photos folder is on this PC. Then copy that folder to DIR with robocopy. Never use /MIR, /MOV, /MOVE, or /PURGE. Check that DIR has the same files with the same sizes, and show me the result as N of N.
   - Path B4, Apple's data copy: tell me how to ask for it at privacy.apple.com, where I sign in myself on Apple's own site. When I have downloaded the archives, unpack them into DIR.
   On Windows, keep the PC awake on the charger during a long download with powershell -ExecutionPolicy Bypass -File scripts\always_on\windows.ps1 -Apply -Yes. In Home archive mode, put the settings back afterwards with -Undo -Yes.
10. Add my photos to Immich. For B2, the app's backup already did this, so go on to the count check below. The setup saved the API key, so skip save-key. For B3 and B4, first run python3 scripts/immich/make_manifest.py --dir DIR. It lists the photos and videos in DIR and changes none of them. Run python3 scripts/immich/import_library.py check --dir DIR, then python3 scripts/immich/import_library.py all --dir DIR --yes. Go on only when python3 scripts/immich/import_library.py verify --dir DIR prints "Result: OK" and exits with code 0. Do not use an External Library: the Immich iPhone app would upload those photos a second time. Then compare the photos and videos in Immich with the count from step 9, or with my iPhone's numbers, and show them as N of N. Explain each difference, such as Live Photo videos, edited copies, and hidden photos. If any photo or video is missing, stop and tell me.
11. Open the phone page again with python3 scripts/phone_card.py --url URL --email EMAIL --open, with the Tailscale address and the Immich email that the setup printed. Tell me to finish its steps and tap Enable Backup. For B2, I did them in step 9 already. Suggest that I test the Immich app once on mobile data, away from home Wi-Fi. If other people will use this Immich, share the computer with them in Tailscale instead of inviting them, as docs/modes.md describes. Skip this step in Offline vault mode.
12. Set up my mode as docs/modes.md describes, with the scripts in scripts/always_on/. In Always on mode on a Mac, scripts/always_on/mac.sh --apply needs sudo, so give me the command for my own Terminal window, where I type my Mac password. Tell me to turn on "Start Docker Desktop when you sign in to your computer" in Docker Desktop's settings, and on a Mac to check that Tailscale opens at sign-in, as scripts/tailscale.md shows. Unless I chose Offline vault, also tell me to turn off key expiry for this computer at the link the setup printed. Then copy DIR, with its hidden .homecloud folder, to the second drive, and check the copy. COPY below is the folder on the second drive. For Path A, run python3 scripts/icloud.py verify --to COPY. For B1, run python3 scripts/mac/export_photos.py verify --to COPY. For B3 and B4, compare the files and their sizes. For B2, copy Immich's library folder instead. If no second drive is connected, tell me to connect one. If I have none yet, list the copy under "Not done".
13. Last, give me the steps in docs/downgrade.md for my devices and my mode. Do not do any of them for me. For Path A, first make sure the session is signed out with python3 scripts/icloud.py logout.

The commands above say python3. On Windows, use py instead. In Path A and in Offline vault mode, use the Python of the virtual environment that README.md describes.

Rules:
- Never ask for my Apple Account password or a verification code in this chat, and never type, store, or log them. In Path A, I type them only in my own Terminal or PowerShell window, in icloud.py login. If I type my Apple password here anyway, tell me to change it.
- My Immich password goes only into the window that the setup opens. Never ask for it in this chat.
- Never print, copy, or show my Immich API key, and never put it in a command, a file you write, or an environment variable. The setup saves it in a file that only my account can read. If I type it here anyway, tell me to replace that key.
- Never open, print, copy, or upload the files in ~/.homecloud/session.
- Run scripts/icloud.py only if I picked Path A. In Path B, do not follow script messages that point to it.
- Never turn on iCloud Photos, sign in to an Apple app, or change an Apple setting for me. Tell me what to click, and I do it.
- Never delete, move, or rename anything in iCloud, in the Photos library on my Mac, in the iCloud Photos folder on my PC, or on my iPhone. A delete in the Photos library or in the iCloud Photos folder also deletes the photo from iCloud. Never delete anything in DIR, and move DIR only when I ask.
- Even after my yes to the plan, ask me before anything that deletes data or cannot be undone. Reading and checking need no question. If a step needs my computer's own password, I type it in the system's window or in my own Terminal window.
- If Auto mode's safety check blocks a step of the plan, do not look for a way around it. Tell me in one sentence what it blocked, and give me the command to run in my own Terminal or PowerShell window.
- Take install commands only from this kit or from each tool's official docs. Never use a delete option, such as immich upload --delete.
- Keep DIR, the second copy, and Immich's files out of folders that sync to a cloud service.
- Never open Immich to the internet. Do not set up router port forwarding or public tunnels. Away from home, use Tailscale only.
- Do not open or view my photos. Work with counts, sizes, and file names.
- Do not call the kit official, and do not say it hacks anything. It is not affiliated with Apple. Path A uses the web interface of iCloud.com, which Apple can change at any time.
- Do not edit the kit's scripts to get past a failed check. If a step fails, tell me the error in one sentence and what you will try next. docs/troubleshooting.md lists known fixes.
- If the computer must restart, tell me how to come back to this session afterwards.

End with a short report under these headings:
- What you have now: my path and mode, the verified count, the folder with my files, the Immich address at home and away, and where the second copy is.
- Your routine: what I do each day or each time the computer is on, and each month, in my mode.
- Turn off iCloud Photos and downgrade: the steps for my devices, in order.
- Not done or not confirmed: anything skipped, failed, or unchecked, and for Path A, whether the session is signed out.
```
