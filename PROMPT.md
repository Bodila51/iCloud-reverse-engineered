# The Homecloud prompt

Before you paste it, switch Claude Code to **Auto** mode, so it runs commands without asking you each time: in the Claude desktop app's **Code** tab, choose **Auto** in the mode menu under the prompt box (Cmd+Shift+M on a Mac, Ctrl+Shift+M on Windows); in a terminal, press Shift+Tab until it shows **auto mode on**.

Then copy the text in the box below, and paste it into Claude Code on the computer that will keep your photos. On GitHub, the copy button is at the top right of the box.

Claude Code checks your computer by itself and explains the ways to move your photos. Then it asks you at most two questions, in one message: where your photos are and which way you pick, and whether this computer stays on at home. It shows you one plan, with the few things you do yourself, and waits for your yes. After that, it runs the plan to the end. It asks again only before a step that deletes data or cannot be undone. Homecloud itself never deletes anything. [docs/two-paths.md](docs/two-paths.md) compares the two ways for iCloud Photos, and [docs/google-photos.md](docs/google-photos.md) explains the way for Google Photos.

If **Auto** is not in the menu, keep the mode you have. Claude Code then asks before each command, and you approve each one.

Tell me in one line what you are doing at each stage, and say clearly when you need me.

3. From what you found, pick a folder for the copy, called DIR below, with room for the whole library. For Path G, DIR must be a new folder that a web page may save into: not my home folder, Desktop, Documents, or Downloads themselves, and not a system folder. I type my Apple Account password once, in my own Terminal or PowerShell window, and it goes only to Apple. Until it signs out at the end, a session key in ~/.homecloud/session opens what iCloud.com opens: Photos, iCloud Drive, Notes, Contacts, Calendar, Reminders, iCloud Mail, and Find My. It does not open Keychain passwords, Messages, or Health. Any program that runs as me on this computer could read the key. The script sends only read requests to Photos. It is unofficial, so a change at Apple can break it. With Advanced Data Protection, I must allow web access on my iPhone first.
   - Path B, no sign-in: Apple's own apps download the originals with the sign-in I already have. Nobody asks for my Apple password, and no key stays on this computer. B1 is the Photos app on a Mac, and the only option that checks every file against its original. B2 is the Immich app on my iPhone, with any computer, and takes hours or days for a big library. B3 is iCloud for Windows on a PC, whose drive C: needs room for the whole library. B4 is Apple's data copy at privacy.apple.com, which can take up to 7 days and arrives as zip archives. B2, B3, and B4 compare the counts with my iPhone.
   - Path G, Google Photos: scripts/google/google_photos.py prepares a browser script that I paste into the console of my own signed-in photos.google.com tab, in Chrome, Edge, Brave, Arc, Vivaldi, or Opera. The script repeats the web app's internal requests: it lists my library, compares its size with the free space, and downloads every item into DIR. Files that the page may not fetch itself come as zip files into my Downloads folder, and status and verify unpack them into DIR and delete each zip file once every file in it is in DIR. It only reads, never sees my Google password, never reads my cookies, and saves nothing that could open my account. At the end, verify checks every file against the list that the script read from Google, as N of N. Say the risks plainly: Google's terms forbid reverse engineering and some automated access; Google can suspend or close my whole Google Account, with Gmail, Drive, and YouTube, although no case was found for read-only tools that run in my own tab; the internal requests can change any day; I paste only this kit's script, because scammers use the console too; typing allow pasting switches the console's paste warning off in that browser profile until I reset it after the move; items saved in Storage saver have no original; Locked Folder and Trash are not included. Every way is fine, so never push me to one. If my photos are in both clouds, plan both moves, one after the other, each into its own DIR.
   b. Will this computer be at home and switched on most of the day? Yes means Always on mode. No means Home archive mode. If I ask for Hybrid or Offline vault instead, use that mode. Hybrid is for iCloud Photos, and Offline vault is for an iPhone, as docs/modes.md explains.

On Windows, if py is not found right after the setup installed Python, run it by the full path that the setup printed, in double quotes, or restart Claude Code. On Windows, exit code 3 means Windows must restart to finish WSL 2: tell me the sentence it printed and how to come back to this session, and run the same command again after the restart. In Offline vault mode without Immich, skip this step; on Windows without py, first run winget install --exact --id Python.Python.3.12 --source winget --scope user --silent --accept-package-agreements --accept-source-agreements --custom InstallLauncherAllUsers=0, the setup's own command. With Immich, add --no-tailscale on a Mac or -NoTailscale on Windows. When the phone page opens, tell me I can install the two apps and sign in now, and tap Enable Backup when you say so. For Path B, if you do not know it yet, ask me to read it on my iPhone under Settings > my name > iCloud. For B2, B3, and B4, ask me at the same time to read the number of photos and the number of videos, as README.md describes. I type them here. These numbers are not secret.
